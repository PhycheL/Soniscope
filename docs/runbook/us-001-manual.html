总览完成判据 & 红线

下方 A~I 九个块的所有检查项打勾 + docs/runbook/cloud-setup.md 含全部非敏感信息 = US-001 完成。

本项目实际选用 region OSS / FC / NLS 全部使用 cn-beijing（华北2 北京）。PRD 文本默认建议 cn-hangzhou，已在本手册和 cloud-setup.md 中统一调整为北京。后续所有 endpoint、域名白名单、环境变量都以 cn-beijing / oss-cn-beijing.aliyuncs.com 为准。

六类外部依赖

① 阿里云资源账号、OSS 私有 Bucket、RAM 两个子账号 + 一个角色、FC 3.0 两个 Web 函数槽位（region: cn-beijing；FC 3.0 已无"服务"层级）
② 微信小程序AppID、AppSecret、服务器域名白名单、体验者真机 openid
③ 云端语音转文字 API默认阿里云 NLS 录音文件极速版；AppKey + 调用凭证
④ 测试音频素材4 段标准音频（3 wav + 1 m4a），存于 OSS 私有 bucket，本地 tests/audio/ 经脚本拉取，记录 sha256
⑤ Worker 运行环境任意可跑 Python 3.11+ 的主机；$SONISCOPE_HOME 工作目录（默认 ~/SoniScope/）
⑥ 凭证注入FC 环境变量（11 项）+ Worker ~/SoniScope/config.yaml（chmod 600）

红线（违反即否决，无例外）

  1. 小程序代码内 绝不 包含任何长期 AccessKey 或业务密钥。
  2. Worker 任何路径 绝不 调用 OSS DeleteObject。
  3. STS 凭证必须 精确到单个 object key，不带通配符；有效期 ≤ 15 分钟。
  4. FC 接口必须有 openid allowlist 校验，不接受匿名调用。
  5. 明文 AK / Secret 不进 git；FC 走环境变量，Worker 走 ~/SoniScope/config.yaml（chmod 600）。
⚠ 操作顺序 必须按 A → B → C → D → E → F → G → H → I 顺序，因为 B 块创建的角色 ARN 要填进 H 块 FC 环境变量；E 块拿到的 AppKey 要填进 H 块 Worker config.yaml。

A阿里云账号 + OSS 私有 Bucket

目标：拿到一个能存音频的私有 Bucket，未鉴权访问必须被拒。

操作步骤

  1. 访问 aliyun.com，注册账号 → 账号中心 → 实名认证（个人主体，提交身份证 + 人脸识别）。
  2. 账号中心 → 充值 ≥ ¥100 作为押金（防欠费导致服务暂停）。
  3. 开通 对象存储 OSS 服务（首次进入控制台会引导开通）。
  4. OSS 控制台 → Bucket 列表 → 创建 Bucket，填写如下参数：
    Bucket 名称soniscope-audio（全球唯一，若已被占用可加后缀如 soniscope-audio-yyy，并同步更新本手册全部引用）
    地域华北2（北京） = cn-beijing（本项目实际选用；PRD 原默认 cn-hangzhou 已调整。必须与后续 FC / NLS 同 region，避免跨区流量费）
    存储类型标准存储 Standard
    读写权限 ACL私有 private（绝对不能选 public-read）
    同城冗余 / 版本控制本期 MVP 全部关闭
    服务端加密本期不开（后续阶段评估）
  5. （可选）本地安装 ossutil 命令行工具：官方安装文档。用临时 AK 配置好 profile，便于后续验收。

验收清单

⚠ 验收要点 反例验证（A6）必须返回的是 <Code>AccessDenied</Code> 这种 XML 错误。如果返回 404 或 NoSuchBucket，说明 ACL 配错；如果能直接看到内容，立即把 ACL 改回 private。

BRAM：两个子账号 + 一个角色 + STS 反例验证

目标：FC 拿一个临时凭证 → 临时凭证只能写指定 object key，不能列、不能读、不能越界，且 15 分钟后自动失效。

B-1 创建子账号 soniscope-fc（供 FC AssumeRole）

  1. RAM 控制台 → 身份管理 → 用户 → 创建用户。
  2. 登录名 soniscope-fc，访问方式 只勾选「OpenAPI 调用访问」（不勾控制台登录）。
  3. 创建成功后会显示 AccessKey ID + AccessKey Secret，立即复制保存到密码管理器（1Password / Bitwarden）。Secret 关掉后无法再次查看。
  4. 添加权限 → 系统策略 → 搜索并勾选 AliyunSTSAssumeRoleAccess（只这一条，不要给 OSS 任何权限）。

B-2 创建子账号 soniscope-local-reader（供 Worker 拉音频）

  1. RAM → 用户 → 创建用户，登录名 soniscope-local-reader，访问方式同样只勾 OpenAPI。保存 AK / Secret。
  2. RAM → 权限管理 → 权限策略 → 创建权限策略，名称 soniscope-bucket-readonly，脚本编辑模式贴入： 
    {
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:GetObject",
        "oss:HeadObject",
        "oss:ListObjects"
      ],
      "Resource": [
        "acs:oss:*:*:soniscope-audio",
        "acs:oss:*:*:soniscope-audio/*"
      ]
    }
  ]
}
  3. 给 soniscope-local-reader 添加权限 → 自定义策略 → 勾选 soniscope-bucket-readonly。
✗ 红线提醒 FC 用的 soniscope-fc 子账号 绝不 直接绑 OSS 写权限。FC 写 OSS 必须走 STS AssumeRole 流程，临时凭证精确到单 object key。

B-3 创建角色 soniscope-uploader-role（FC 扮演它来签发 STS）

  1. RAM → 身份管理 → 角色 → 创建角色 → 选择 「阿里云账号」。
  2. 角色名 soniscope-uploader-role，选择信任的云账号 = 当前账号。
  3. 创建后 → 信任策略管理 → 修改信任策略为「精确到 soniscope-fc」： 
    {
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "sts:AssumeRole",
      "Principal": {
        "RAM": [
          "acs:ram::<主账号 UID>:user/soniscope-fc"
        ]
      }
    }
  ],
  "Version": "1"
}
    主账号 UID 在右上角头像 → 账号管理 → 安全设置 中可看，纯数字。
  4. 创建自定义权限策略 soniscope-upload-template（作为模板上限）： 
    {
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject"
      ],
      "Resource": [
        "acs:oss:*:*:soniscope-audio/recordings/*"
      ]
    }
  ]
}
  5. 把该策略授给角色 soniscope-uploader-role。
  6. 记录角色 ARN：形如 acs:ram::123456789:role/soniscope-uploader-role，后面 H 块要填进 FC 环境变量。

B-4 4 个反例验证（用 aliyun CLI）

先用 soniscope-fc 的 AK 调一次 AssumeRole 拿临时凭证，再分别尝试 4 种越界 / 失效操作。

# 1) 配置 aliyun CLI（用 soniscope-fc 的 AK）
aliyun configure --profile soniscope-fc

# 2) AssumeRole 拿临时凭证（policy 收紧到单 object key，有效期显式限制为 900 秒）
aliyun sts AssumeRole \
  --profile soniscope-fc \
  --RoleArn acs:ram::<UID>:role/soniscope-uploader-role \
  --RoleSessionName test \
  --DurationSeconds 900 \
  --Policy '{"Version":"1","Statement":[{"Effect":"Allow","Action":["oss:PutObject"],"Resource":["acs:oss:*:*:soniscope-audio/recordings/test.wav"]}]}'

# 拿到 AccessKeyId / AccessKeySecret / SecurityToken，导出到环境变量
export OSS_AK_ID=<tmp ak id>
export OSS_AK_SECRET=<tmp secret>
export OSS_TOKEN=<tmp security token>
必须全部按预期"失败"的反例
反例 1用上述临时凭证 PutObject 到 recordings/evil.wav（不在 Policy 内）→ 必须返回 AccessDenied。
反例 2用同一临时凭证 ListObjects → 必须返回 AccessDenied。
反例 3用同一临时凭证 GetObject recordings/test.wav → 必须返回 AccessDenied（凭证只有 PutObject 权限）。
反例 4等待 16 分钟后用同一临时凭证再 PutObject → 必须返回 ExpiredToken（凭证有效期已通过 --DurationSeconds 900 显式指定为 15 分钟）。

C函数计算 FC 3.0：两个 Web 函数 + HTTP 触发器

目标：留好两个 hello-world 函数 URL。真实业务代码 + 部署由 US-003（issue-credential）和 US-005（verify-upload）AI 实现，本块仅准备槽位。

⚠ FC 3.0 与 PRD 原文差异 阿里云函数计算已升级到 FC 3.0，取消了"服务"层级，函数变成顶级实体。PRD 原文写的"服务 soniscope-svc + 两个函数"在 FC 3.0 控制台不存在"创建服务"这一步，直接创建函数即可。URL 格式也从 FC 2.0 的 /2016-08-15/proxy/<svc>/<fn>/ 变为 FC 3.0 的 https://<url-id>.<region>.fcapp.run/。本手册和 cloud-setup.md 均已按 FC 3.0 调整；后续 AI 在 US-003 / US-005 部署时也以函数为单元（无服务概念）。

操作步骤

  1. 访问 函数计算 FC 3.0 控制台，确认顶部 banner 显示 「函数计算 FC 3.0」。首次进入会自动创建服务关联角色 AliyunFCDefaultRole。
  2. 右上角切换到地域 华北2（北京）cn-beijing（必须与 OSS 同 region）。
  3. 左侧菜单 → 函数管理 → 函数列表 → 蓝色「创建函数」按钮。
  4. 创建第 1 个函数 issue-credential，按下表填写（其余字段保持默认）：
    创建方式选择 「Web 函数」（FC 3.0 推荐方式，会自动配置 HTTP 触发器；选「事件函数」也行但要再手动加触发器）
    函数名issue-credential（kebab-case，会出现在 HTTP URL 子域名前缀里）
    运行时Python 3.11（或 3.10 / 3.12，按当前 FC 3.0 支持列表）
    代码上传方式使用示例代码（hello world）—— 业务代码由 US-003 用 SDK / s.yaml 部署覆盖
    启动命令 / 监听端口保持默认（Python Web 函数默认 9000 端口）
    请求处理程序类型处理 HTTP 请求
    规格0.35 vCPU / 512 MB（最小配置即可，hello world 占用极小）
    触发器（自动创建）认证方式 = 无身份认证（anonymous），请求方式 = GET + POST，公网访问 URL = 开启（FC 3.0 默认会同时给一个内网 URL，本期只需公网）
  5. 函数创建完成后会自动跳转到「函数详情」。进入 配置 → 触发器 页签，复制 HTTP 触发器的公网访问地址（FC 3.0 格式：https://<url-id>.cn-beijing.fcapp.run/；<url-id> 通常形如 issue-credential-xxxxxxxx，由系统分配，不可自定义）。⚠️ 注意：本项目实际分配到的 url-id 是 issue-cedential-ottfirocds（少一个 r，不是 credential）——这是系统真实分配值，已核实，勿当 typo 修正，详见 cloud-setup.md §3.2 的「勿改拼写」说明。
  6. 返回函数列表，重复步骤 3-5，创建第 2 个函数 verify-upload，配置完全相同。复制其公网访问 URL。
  7. 把两条 .fcapp.run URL 记录到 docs/runbook/cloud-setup.md §3.2。
命名约定 函数目录用 snake_case（apps/fc/issue_credential/），FC 控制台函数名用 kebab-case（issue-credential）。FC 3.0 的 URL 子域名包含函数名前缀，所以 kebab-case 命名是强制约定。AGENTS.md 已明示。
✗ 触发器认证方式必看 FC 3.0「认证方式」选项中：
① 无身份认证（anonymous） —— 本期选这个，业务层走 US-003 实现的 openid allowlist；
② 函数计算签名认证（sig） —— 客户端必须用 FC AK 对请求签名，小程序无法做到。
如果第一次创建时选错了 sig，去「触发器」页签 → 编辑触发器 → 改回「无身份认证」，无需重建函数。

D微信小程序：账号 + AppID + 域名白名单 + 工具 + 真机 openid

目标：拿到 AppID / AppSecret / 真机 openid 三件套，且 FC + OSS 域名已加入小程序合法域名白名单。

D-1 注册小程序账号

  1. 访问 mp.weixin.qq.com → 注册 → 小程序（个人主体即可）。
  2. 填写邮箱 / 设密码 / 邮件激活 → 选择主体类型「个人」→ 微信扫码绑定管理员。
  3. 登录小程序后台，记录 AppID（形如 wx1234567890abcdef）。
  4. 开发管理 → 开发设置 → 重置 AppSecret（首次需管理员扫码），立即保存到密码管理器。

D-2 配置服务器域名白名单

  1. 小程序后台 → 开发管理 → 开发设置 → 服务器域名 → 修改。
  2. 在 request 合法域名 添加 两个 FC 3.0 函数的完整公网 host（去掉路径，只填 https + host）。注意：FC 3.0 每个函数的子域名都不同，需要分别添加两条，微信不支持通配符：
    https://issue-credential-xxxxxxxx.cn-beijing.fcapp.run
    https://verify-upload-yyyyyyyy.cn-beijing.fcapp.run
    实际的 xxxxxxxx / yyyyyyyy 部分从 C 块复制下来的 URL 中提取；上限：request 域名最多 20 个，足够本期使用。
  3. 在 uploadFile 合法域名 添加 OSS Bucket 域名：
    https://soniscope-audio.oss-cn-beijing.aliyuncs.com
  4. 保存（每月最多修改 50 次，无需担心配额）。
⚠ 注意 微信要求域名必须是 https，且不能包含端口、路径。FC 默认给的 .fcapp.run 域名是 https，可直接用。如未来切自定义域名，需重新配置白名单。

D-3 安装微信开发者工具 + 创建项目

  1. 下载 微信开发者工具（稳定版 Stable Build）。
  2. 安装并扫码登录。
  3. 新建项目 → 小程序 → 填入 AppID（D-1 记录的）→ 项目名随意 → 选择本地空目录（用于测试，不必与 repo 关联）→ 不使用云开发 → 创建。

D-4 加入体验者 + 拿真机 openid

  1. 小程序后台 → 管理 → 成员管理 → 体验成员 → 添加体验者 → 用本人微信扫码确认。
  2. 在开发者工具中，把下面这段代码贴到 app.js 的 onLaunch 里临时跑一次： 
    wx.login({
  success: (res) => {
    console.log('JS code:', res.code);
    // 用这个 code 去服务端调 jscode2session 拿 openid
  }
});
  3. 在终端用 curl 调用微信接口换 openid： 
    curl "https://api.weixin.qq.com/sns/jscode2session?appid=<AppID>&secret=<AppSecret>&js_code=<上一步的 code>&grant_type=authorization_code"

# 返回示例：
# {"session_key":"...","openid":"o6zAJs...."}
  4. 把 openid（形如 o6zAJs...，28 字符左右）记录到 runbook，用作 FC 环境变量 OPENID_ALLOWLIST 的值。

E云端语音转文字 API（默认阿里云 NLS 录音文件极速版）

目标：开通 ASR 服务，拿 AppKey，并完成一次官方 demo 联调验证转写质量。

为什么默认 NLS ① 与现有阿里云账号同一身份体系；② 与 OSS 同 region 流量便宜；③ 录音文件极速版支持直接传 OSS 公网/签名 URL 让 API 自己拉，Worker 不需要把音频重传给 ASR。备选：通义听悟 / OpenAI Whisper API（如选备选需在 runbook 中记录变更原因 + 影响哪些 stories）。

操作步骤

  1. 访问 智能语音交互控制台，立即开通服务（同账号同 region）。
  2. 左侧菜单 → 全部项目 → 创建项目，名称 soniscope-mvp，业务场景选「录音文件转写」。
  3. 项目创建后，复制 AppKey（项目级标识，约 16 字符）保存到 runbook。注意：AppKey 不是 AccessKey，可入 runbook。
  4. 调用 API 的 AccessKey 复用 A 块账号下的另一个 RAM 子账号（如已用 soniscope-fc 不要复用，建议新建一个 soniscope-asr 子账号并授予 AliyunNLSFullAccess），AK / Secret 保存到密码管理器。
  5. 查看免费额度：智能语音交互 → 资源中心 → 资源包，确认录音文件转写免费时长（通常每月若干小时）。
  6. 真实联调基线：用官方 demo 或 curl 调用录音文件极速版，提交 F 块准备的 sample-20s.wav 的 OSS 公网 URL，等待返回结构化结果。官方文档。
  7. 把返回 JSON 的关键字段（含完整文字 + segments + 时间戳）粘贴到 runbook 作为基线参考，方便后续比对。

成本估算（参考）

场景日均 30 分钟录音 × 30 天 = 15 小时/月
NLS 录音文件极速版按小时计费，免费额度通常足够个人使用；超出部分约 ¥1.4/小时
OSS 存储15 小时 ≈ 1.6 GB WAV/月（16kHz 单声道 PCM），按 OSS 标准存储计费每月仍约 ¥0.2，几乎可忽略

F测试基线音频素材

目标：准备 4 段标准音频（3 wav + 1 m4a），上传到 OSS 私有 bucket，本地 tests/audio/ 经脚本拉取并提供 sha256，供 US-015 / US-017 + §4 最终验收复用。音频不进 git。

需要准备的 4 个文件

文件用途 / 时长 / 格式
sample-20s.wav约 20 秒 wav，清晰人声，无背景音。US-001 E 联调 + US-017 真实闭环用。
sample-54s.wav约 54 秒 wav，含 5~10 句话。P-01 性能基线 + US-017 性能验证用。
sample-25min.wav约 25 分钟 wav。US-010 长录音分片 + §4.2 手动验收闭环用。
sample-20s.m4a约 20 秒 m4a（容器内为 AAC）。验证 AAC/m4a 转码（OQ-1 / US-015 强依赖）。

操作步骤

  1. 准备 4 段音频：3 段 wav（约 20s / 54s / 25min，念新闻、读书摘录或自由讲话皆可）+ 1 段 m4a（约 20s，容器内为 AAC，用于验证 Worker 转码）。
  2. 把 4 个文件上传到 OSS 私有 bucket soniscope-audio 的 sample/ 前缀下（如 sample/sample-20s.wav）。音频不进 git。
  3. 把每个文件的 sha256 + 用途 + 时长登记到 tests/audio/fixtures.manifest.json 与 docs/runbook/cloud-setup.md §6：
