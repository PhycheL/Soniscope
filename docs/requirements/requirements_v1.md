# 日观声记 · 系统设计思路

## 一、目标

为个人记录流水账日记。任何时候想起来都可以对着软件说几句，晚上再系统地总结一次。

- 声音必须保存
- 语音自动转为文字
- 每天整理成一份文字稿

---

## 二、两个核心实体

### 碎片记录（Fragment Record）

> 代表「发生过的事实」，是每次说话的原始输入。

- **包含**：录音时间、原始音频文件、语音直转的原始文字
- **特性**：只读、只增不改；转出来的文字不管多乱，原样保留

### 每日文字稿（Daily Journal）

> 代表「整理后的日记」，是当天所有碎片记录的加工结果。

- **包含**：日期、经大模型润色排版后的通顺文字
- **特性**：可反复覆盖生成（晚上补录后可重新生成覆盖旧稿）

---

## 三、运作流程

```
随时录音  →  自动转写  →  晚上整理  →  保存文字稿
```

1. **随时随地记录**：按下按钮说话，松开发送；系统将音频存盘并记录时间
2. **自动转写**：立刻调用语音转文字服务，将文字与音频路径一起保存
3. **晚上整理成稿**：将当天所有 `raw_text` 按时间顺序拼接，发给大模型润色
4. **保存结果**：将大模型返回的文字保存为当日文字稿

---

## 四、设计原则

- **随时可用，方便快捷**：日常记录时必须保证极低摩擦
- **极薄前端 + 核心后端**：前端只负责采集，后端负责业务与存储

---

## 五、技术方案：阿里云 OSS + 本地 Python

> 不需要租 ECS、不需要自己写后端，直接用 OSS 作为「文件暂存信箱」。

### 架构

| 层 | 组件 | 职责 |
|---|---|---|
| 手机端 | 微信小程序 | 录音结束后，直接将音频上传至阿里云 OSS |
| 云端 | 阿里云 OSS | 静默存储文件，无计算能力 |
| 本地 | Python 脚本（家里电脑） | 每分钟轮询 OSS → 下载新文件 → 删除云端文件 → Whisper 转写 → 存入 SQLite → 晚上调用大模型写日记 |

### 数据可靠性：本地闭环

> 问题：录完音直接上传，遇到网络切换或微信被杀后台，临时文件会永久丢失。

**解决方案**：在微信小程序内部建立「先落盘 → 排队上传 → 成功后销毁」的本地闭环。

- 利用微信小程序原生文件系统和本地缓存
- 手机端对自己产生的数据负责，直到云端签收为止
