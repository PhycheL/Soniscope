## 1. 项目档案

SoniScope 是一条个人语音流水账工具的完整流水线：微信小程序录音 → 阿里云 FC 3.0 函数签发 STS 凭证 → OSS 私有桶存储 → 本地 Worker 轮询下载、ffmpeg 标准化、NLS 云端转写落盘。工程上项目已走完全程：PRD → tech-spec → 实现 → E2E 验收 → 上线前审计（v1.0 审计里程碑已关闭，v1.1 上线前修复里程碑刚启动即中断）。

中断原因（完整推演见 `docs/decision-2026-07-06-product-pivot.md`）：用户重新定义了需求——**"语音不是重点，内容才是重点"**。真实需求是最低摩擦的思考记录（capture），而 flomo 已覆盖该需求；后续架构定为"flomo 入口 → 自建第二大脑下游"，SoniScope 解的已不是用户的问题。

关键定性：**这不是工程失败，是产品定位失败**。工程质量高——mypy strict 全覆盖、纯逻辑+DI 分层、脚本化验收体系、安全红线结构化保障——但"正确地做事"没能挽救"做了不正确的事"。

## 3. 经验教训

按重要性排序，共 8 条：

1. **需求验证必须先于工程投入**。PRD 的核心承诺"说出口的话 100% 落到云端音频 + 本地文本"是一个未经验证的假设——从未验证过"原始音频对我是资产"；到上线审计阶段才第一次问"我为什么需要这个"，此时全部工程投入已经发生。

2. **PRD 缺失"为什么不用现成产品"章节**。flomo 对比是项目末期才做的；如果立项时强制回答"现有工具（flomo/语音备忘录/Notion）为什么不行"，大概率项目不会启动，或会以完全不同的形态启动。buy vs build 是个人项目也必须回答的问题。

3. **手段与目的混淆**。需求被表述为"语音记录工具"（手段/系统视角），而真实需求是"随时记录思考"（目的/用户视角）；表述错层次导致整个 PRD 围绕语音管道展开。教训：需求必须写成"用户想完成什么"，并追问一层"为什么"。

4. **"100%/绝不"类承诺是复杂度放大器**。数据零丢失承诺驱动了大量复杂性——三段式写入、崩溃恢复、8 状态上传队列、100 条真机录音验收、中断保护——这些复杂性服务于未验证的需求。教训：给承诺定级前先问"这个保证值多少工程成本，用户真的需要吗"。

5. **范围在核心价值未验证时就开始扩张**。`docs/multi-user-design.md`（多用户/对外发布）、FC 直转设计等都在"我自己是否会持续用它"尚无答案时启动。教训：个人项目的第一验收标准是"我持续在用"，未达标前冻结一切扩张。

6. **工程质量不是产品成功的充分条件**。本项目是"高工程质量 + 错误方向"的标本：mypy strict、DI、审计体系一应俱全，但方向错了，这些只是让错误更精致。资源有限时，验证方向的优先级永远高于打磨质量。

7. **止损时机与姿势是这次做对的部分**。在上线前（而非上线后被维护成本拖着）主动发起定位质疑；止损时不是删库跑路，而是系统性沉淀（3 份文档 + 资产指针）——这套"体面中断"流程本身值得复用。

8. **优雅降级是好架构的试金石**。SoniScope 全链路都活着才有价值（Mac 关机/Worker 挂/NLS 欠费任一环断掉产出为零）；flomo 入口方案则入口独立成立。教训：偏好"部分完成也有价值"的架构与路线图排序。

## 4. 未来项目成功率提升清单

按立项/执行/收尾三阶段分组，共 8 条可操作项。

### 4.1 立项阶段（最重要，成本最低的杠杆）

1. **写一页"问题陈述"**，强制包含三问：我要完成什么（目的层，非手段层）；现有工具为什么不行（逐个列出并给出否决理由）；如果 6 个月后我不再用它，最可能的原因是什么（预演失败）。
2. **用最便宜的方式先验证需求 2 周**：现成工具拼接、手动流程、快捷指令——先证明"我会持续做这件事"，再考虑自建。本案例：先用 flomo 语音输入记两周，看是否真的需要原始音频，就能省掉整个项目。
3. **预先定义 kill criteria（放弃条件）与检查点**：例如"连续两周没有真实使用则暂停""每个里程碑结束重新回答一次：这还是我的问题吗"。

### 4.2 执行阶段

4. **每个里程碑的第一个验收项是"我本人在真实使用它"**，其余指标（成功率/性能/安全）都排在后面。
5. **承诺分级**：把"绝不/100%"类承诺列成清单，逐条标注它带来的工程成本，砍掉需求方（自己）不愿为之付费的。
6. **冻结扩张**：核心价值未被使用数据证实前，不写任何扩展设计文档（多用户/平台化/新链路）。
7. **控制常驻成本**：个人项目优先选事件驱动/无常驻进程/免费额度内的架构；每月云账单是持续的"这个项目还值得吗"信号。

### 4.3 收尾阶段（无论成败）

8. **像本次一样体面收官**：决策记录 + 经验手册 + 复盘三件套；可复用代码资产留指针；tag 归档不删库。失败项目的沉淀质量决定它是"学费"还是"浪费"。
