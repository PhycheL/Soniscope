## Codebase Patterns
- Monorepo managed by uv workspace at the root — `pyproject.toml` only declares workspace members, no business deps.
- Worker is an independent uv sub-project under `apps/worker/` with its own `pyproject.toml` and `.venv`.
- `uv run --directory apps/worker <cmd>` as the standard invocation pattern from the project root.
- Makefile paths are relative to `apps/worker/` (e.g. `src/` not `apps/worker/src/`) because `uv run --directory apps/worker` changes CWD.
- mypy strict mode enforced from day one; `--strict` flag in Makefile.
- ruff for linting (not flake8 or pylint).
- pytest for testing; tests must exist — pytest exits with code 5 (failure) when no tests are collected.
- Pydantic v2 `model_validate()` is the canonical way to construct models from raw dicts.
- Secret masking: override `__repr__`, `__str__`, and `model_dump()` on Pydantic models; use a recursive `_mask_dict()` helper that knows which field names are sensitive.
- Config loading: `yaml.safe_load()` → `model_validate()` → catch `ValidationError` to extract and list all missing fields at once.
- Runtime dir initialization uses `Path.mkdir(parents=True, exist_ok=True)` for idempotent creation.
- `typer.Exit(code=1)` is how CLI commands signal non-zero exit; error messages go to stderr via `err=True` on `typer.echo()`.
- `typer.testing.CliRunner` is the standard way to test Typer CLI commands in pytest.
- `scripts/` 下独立脚本不在 uv workspace 内，测试时应 `sys.path.insert(0, ...)` 导入函式，而非 subprocess 调用。
- ffprobe `-of csv` 输出对含逗号的 format_name 加引号，需 `.strip('"')` 处理。
- `subprocess.run()` 运行在独立解释器中，patch 模块级常量无效 — 只测函式逻辑。
- FC 3.0 目录约定：源码用 snake_case（`issue_credential`），云端函数名用 kebab-case（`issue-credential`），`FUNCTION_DIR_MAP` 映射两者。
- FC 函数间共享代码放在 `apps/fc/shared/`，每个函数独立打包时以 `shared/` 前缀写入 zip。
- FC 共享模块优先使用 Python stdlib（`urllib.request`、`hmac`、`hashlib`），减少部署依赖。
- FC safe_handler 是统一包装器：JSON 解析 → 字段校验 → 鉴权 → 业务逻辑 → 错误映射 — 新 FC 函数只需实现 `_handle(data, openid, t_start)`。
- `apps/fc/<function>/` 目录需要 `__init__.py` 文件才能被 pytest 以包形式导入测试。
- 阿里云云 API（STS 等）HMAC-SHA1 v1 签名使用 `GET&%2F&<percent-encoded-canonical-query>` 模式签名。`SignatureNonce` 用 `uuid.uuid4().hex`。
- AuthError 支持 `extra` dict 字段，在 auth_error_to_response 中合并到 JSON body — 用于 SIZE_EXCEEDED 等需要额外字段的错误响应。
- 当 SharedConfig (NamedTuple) 增加字段时，所有测试的 `_set_env` fixture 和 `os.environ.update({...})` 都需要补齐新字段。
- 微信小程序每个页面必须有 .js/.json/.wxml/.wxss 四个文件；project.config.json 中 urlCheck=true 确保域名校验生效。
- 小程序常量定义在 utils/constants.js 中集中管理（FC URL、OSS domain、分片阈值、状态枚举），不使用 process.env。
- 小程序安全日志工具（utils/logger.js）对敏感字段名（access_key_secret/appsecret/token 等）自动脱敏，避免打印明文。
- `node -c` 用于 Makefile 中的小程序 JS 语法快速检查。
- 小程序测试用纯文件内容正则匹配验证代码结构和字段存在性，不模拟 wx API 调用（微信 API 只能在 DevTools/真机环境运行）
- 小程序前端 SHA-256 使用纯 JS 实现（零填充十六进制：`('0' + byteVal.toString(16)).slice(-2)`），通过 `wx.getFileSystemManager().readFile` 读取文件 ArrayBuffer → Uint8Array → sha256Hex，返回 Promise 保持非阻塞
- 设备短 ID 通过 wx.storage key 持久化（`soniscope_device_short_id`），app.onLaunch 初始化并存入 globalData，各页面通过 `getApp().globalData.deviceShortId` 访问
- Fragment ID 格式：`<YYYYMMDDTHHMMSS>_<deviceShortId>_<26-char-Crockford-Base32-ULID>`，生成逻辑集中在 `utils/idgen.js`，使用 `_pad2()` 辅助函数零填充两位数
- uploadRecord 扩展为包含 `manifest`（完整 Fragment 元数据草案）和 `ossMeta`（全部 7 个 x-oss-meta-* 请求头字段的键值对），为上传流程统一数据契约
- Crockford Base32 字母表：`0123456789ABCDEFGHJKMNPQRSTVWXYZ`（不含 I/L/O/U 避免混淆），ULID 26 字符 = 10 时间戳 + 16 随机
- 草稿确认态使用 `draftPreviewMode` 布尔值替代早期 US-012 的 `draftSaved` 字段，两者语义不同：`draftPreviewMode` 表示整页进入确认态（显示试听/重录/删除/保存并上传），`draftSaved` 只是简单标记草稿已保存。后续测试检查草稿确认态应搜索 `draftPreviewMode`。
